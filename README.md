# 7-Eleven HR System

ระบบบริหารบุคลากรร้าน 7-Eleven (แฟรนไชส์ 3 สาขา) — เว็บล้วน ไม่มีขั้นตอน build
โฮสต์บน **GitHub Pages** · ฐานข้อมูลและงานหลังบ้านอยู่บน **Supabase**

> อัปเดตล่าสุด 7 พ.ย. 2569

---

## โครงไฟล์

```
HR-7-eleven-main/
├── index.html                # หน้าแรก
├── sw.js                     # Service Worker — แก้ไฟล์เว็บทีไร ต้องขยับเลขเวอร์ชันในนี้
├── manifest.webmanifest      # ตั้งค่า PWA
├── .nojekyll                 # ห้ามลบ (บอก GitHub Pages ว่าอย่าใช้ Jekyll)
├── shared/                   # หัวใจของระบบ — ทุกหน้าเรียกใช้
│   ├── config.js             #   URL + anon key ของ Supabase
│   ├── supabase.js           #   ชั้นเชื่อมต่อกลาง
│   ├── hr-api.js             #   ชั้น backend ของหน้า HR
│   └── session.js            #   จัดการ session/สิทธิ์
├── supabase/
│   ├── functions/            # ★ Edge Functions (Deno) — ตัวนี้เท่านั้นที่ deploy ขึ้น Supabase
│   └── *.sql                 # สคริปต์ SQL — เอาไปวางใน SQL Editor รันเอง ไม่ได้ deploy
└── (หน้าเว็บอื่น ๆ ตามตารางด้านบน)
```

## หลักการที่ยึดไว้

1. **ไม่มีขั้นตอน build** — แก้ `.html` / `.js` แล้วอัปขึ้น GitHub ได้เลย
2. **หน้าเว็บคุยกับฐานข้อมูลตรงผ่าน PostgREST ด้วย anon key** (ชั้นกลางคือ `shared/supabase.js` และ `shared/hr-api.js`)
   ส่วน edge function ใช้เฉพาะงานที่ต้องมี service key หรือต้องทำเบื้องหลัง เช่น แจ้งเตือน LINE, รับ webhook, ผู้ช่วย AI
   → แปลว่า **ไม่มีการยืนยันตัวตนรายคนที่ชั้นฐานข้อมูล** ทุกคำขอมาในฐานะ `anon` เหมือนกันหมด (ดู `supabase/rls_template.sql`)
   ข้อมูลที่ไม่อยากให้หลุด ต้องปิดสิทธิ์ตารางแล้วอ่านผ่าน RPC `security definer` ที่ตรวจตัวตนเอง — แบบที่ `sca_items` ทำ
3. **แก้ไฟล์เว็บ = ต้องขยับเลขเวอร์ชันใน `sw.js`** ไม่งั้นมือถือพนักงานยังใช้ของเก่าอยู่
   และ GitHub Pages ใช้เวลา build อีก 1–3 นาทีหลังอัป → เช็กว่าเวอร์ชันบนเว็บจริงขึ้นแล้วค่อยบอกว่าเสร็จ
4. **repo นี้เป็น public** — ห้ามคอมมิตความลับ และห้ามคอมมิตเนื้อหาลิขสิทธิ์
   (คู่มือหลักสูตรของปัญญธารา · เกณฑ์ตรวจ QSSI · แบบตรวจ SCA)
   ของพวกนี้อยู่ในฐานข้อมูลหรือในโฟลเดอร์ `_local-ห้ามอัป-github/` บนเครื่องเจ้าของร้านเท่านั้น

## Edge Functions (20 ตัว)

| กลุ่ม | ฟังก์ชัน |
|---|---|
| ผู้ช่วย AI (นิดา) | `hr-assistant` · `emp-assistant` · `chat-reply` |
| แจ้งเตือน LINE | `staff-notify` · `hr-notify` · `mgr-task-notify` · `announce-notify` · `chat-notify` · `line-goods-notify` · `line-image-push` · `line-webhook` |
| รายงาน/วิเคราะห์ | `sales-digest` · `ai-review` · `ai-review-analyze` |
| อื่น ๆ | `payroll-mail` · `sms-send` · `poster-gen` · `poster-art` · `storage-cleanup` · `storage-orphan-cleanup` |

> ⚠️ `hr-assistant` และ `staff-notify` **ห้ามอัปขึ้น repo นี้** — deploy ตรงที่ Supabase อย่างเดียว

deploy ทีละตัวเฉพาะตัวที่แก้:

```
supabase functions deploy <ชื่อฟังก์ชัน> --no-verify-jwt
```

> ⚠️ `--no-verify-jwt` **ต้องมีเสมอ** เพราะ pg_cron ยิงเข้ามาโดยไม่มี token
> ถ้าลืมใส่ ระบบแจ้งเตือนอัตโนมัติจะเงียบไปทั้งหมด

## คู่มือหลักสูตร + ข้อสอบซ้อม

หน้า HR → แท็บ **คู่มือ** มี 2 อย่าง

- **คู่มือหลักสูตร** ที่ถอดจากวิดีโอบทเรียนของปัญญธารา 2 หลักสูตร
  (ผู้ช่วยผู้จัดการร้าน 35 บท · พนักงานร้าน 37 บท) — นิดาดึงไปตอบคำถามวิธีทำงานหน้าร้านได้
- **ข้อสอบซ้อมจากคู่มือ** 1,808 ข้อ — เลือกหลักสูตร/ขอบเขต/จำนวนข้อ ทำเสร็จเฉลยทันที
  พร้อมบอกว่าอยู่บทไหน นาทีไหน กดย้อนไปดูวิดีโอต้นทางได้

> เนื้อหาคู่มือเป็นลิขสิทธิ์ CP ALL / ปัญญธารา ใช้สอนงานภายในร้านเท่านั้น
> **ไม่ได้เก็บใน repo นี้** — อยู่ในฐานข้อมูล Supabase และในเครื่องเจ้าของร้านเท่านั้น

## เตรียมรับตรวจ: QSSI และ SCA

สองเมนูนี้ทำงานแบบเดียวกัน — **ไฟล์หน้าเว็บอยู่ใน repo แต่เนื้อหาแบบตรวจอยู่ในฐานข้อมูล**
เพราะ repo เป็นสาธารณะ ถ้าฝังเนื้อหาไว้ในไฟล์ ใครก็โหลดไฟล์ดิบอ่านได้โดยไม่ต้องผ่านรหัส

| | QSSI | SCA |
|---|---|---|
| หน้าเว็บ | `qssi/index.html` | `sca/index.html` |
| ตารางเนื้อหา | `qssi_check_items` | `sca_roles` · `sca_items` |
| ตารางความคืบหน้า | `qssi_check_logs` | `sca_check_logs` |
| SQL โครงสร้าง | `supabase/qssi_check.sql` | `supabase/sca_setup.sql` · `supabase/sca_hr_access.sql` |
| ข้อมูลตั้งต้น | — | `_local-ห้ามอัป-github/sca_seed.sql` (**ห้ามอัป**) |
| สิทธิ์อ่าน | `anon` อ่านตารางได้ | ปิด `anon` · อ่านผ่าน RPC ที่ตรวจรหัสพนักงาน |

SCA แยกตามตำแหน่ง (ผจก. · ผช. · พนักงาน · แคชเชียร์ · VOE) และตามผลัด
การติ๊กเก็บรายสาขารายเดือน ผจก. จึงเห็นได้ว่าสาขาเตรียมถึงไหนและใครติ๊ก

## ทดสอบในเครื่อง

กล้องและ GPS ทำงานเฉพาะบน **https หรือ localhost** (เปิดแบบ `file://` ไม่ทำงาน)

```
python -m http.server 8000
```

แล้วเปิด `http://localhost:8000/employee/` หรือ `http://localhost:8000/hr/`
(หรือดับเบิลคลิก `start-server.bat`)
